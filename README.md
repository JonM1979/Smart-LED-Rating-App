# Code Process / Details

In this section I include all the files associated with the project that I used. Thankfully, a lot of the heavy lifting was already done by Random Nerd Tutorials and all the credit goes to their code and the work they put into it. For a more detailed description of what the Arduino code does line by line, please check out the tutorial at this link: https://randomnerdtutorials.com/esp32-data-logging-firebase-realtime-database/  
The code for this project is basically the same as the one used for the original BME280 project; I basically modified the code to take in an extra reading and just replaced the appropriate function calls with the INA219 library for current, voltage, and power. 

Since machine learning is becoming more accesible on edge devices, I decided I wanted to add some machine learning to the project. I wanted for the INA219 and the ESP32 to tell the user an Energy Rating Score (ERS); in the case of this project, it is an arbitrary rating score that I came up with to determine the efficiency of the LED that is plugged into the circuit. The LED ligthbulbs that I used for this project were all 12V DC lightbulbs as to keep in the max voltage range of the INA219. I decided that an ERS of 100 would be the LED running at 12V since these are new lighbulbs and this would be the ideal conditions that they would be running at. To simulate a lighbulb that was maybe older or maybe had a malfunctioning component, an ERS of 75 would be the LED running at 11V. Then an ERS of 50 would be the LED running at 10V and an ERS of 25 would be at 9V; which for the case of one of the LEDs would almost be completley shut off. I ran three different LEDs and recorded 100 datapoints at the above conditions for each measuring their current, voltage, power, timestamp, etc. I recognize that this isn't the most accurate or developed rating system since this is heavily biased towards voltage but the goal was for the machine learning model to be able to give the LED an ERS based off of this dataset. In the future, it would be nice to have some real broken or malfunctioning lightbulbs to make the model more accurate or have a power supply that I can control current in order to handle edge cases better. After recording the data, I was able to train a TensorFlow model with it and compress it into a TFLite model to be able to run on the ESP32. I downloaded the .zip file for the Tensor Flow Lite library from the Tensor Flow github found here: https://github.com/tensorflow/tflite-micro/tree/main and included the necessary files into my Arduino Library folder. Then I added a function that ran the model and returned an ERS value based on the current, voltage, and power of the LED currently present to send to the Firebase along with the other data.

Again, most of the heavylifting was done by Random Nerd Tutorials in integrating the Arduino code with the web app hosted by Firebase; for detail on how to set it up, this is the link to the tutorial: https://randomnerdtutorials.com/esp32-esp8266-firebase-gauges-charts/ 
Here I edited the Javascript, HTML, and CSS files to fit my version of the project. This included me adding some code in the Javascript files to process the extra variables and follow along with the code that was already there on how to process the new variables. Then in the HTML file, I also followed the code that was already there on how to handle the new variables and modified it so that it can show the four variables and their respective charts, gauges, and graphs. 

I know this was a lot for me to process and learn to handle when I first starting doing this project but if anyone wishes to recreate this project and would like some more direction, please email me or use ChatGPT/any AI chat model as it was a super useful tool when learning what the next step was or what an error meant when I got them!
